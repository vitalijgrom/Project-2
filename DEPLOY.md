# Как развернуть дашборд на Cloudflare

Инструкция рассчитана на то, что вы всё делаете сами. Каждый шаг заканчивается
проверкой: увидели описанное — идите дальше; нет — смотрите
[Если что-то пошло не так](#если-что-то-пошло-не-так).

Весь путь занимает 15–20 минут, из них большая часть — ожидание выпуска
сертификата.

В качестве примера поддомена ниже взят `viferon-media.dump.su` — подставьте
свой. Домен должен быть добавлен в тот же аккаунт Cloudflare, где вы создаёте
проект.

---

## Что должно быть под рукой

* Аккаунт Cloudflare с добавленным доменом.
  Проверить: [dash.cloudflare.com](https://dash.cloudflare.com) → **Websites** →
  домен в списке со статусом **Active**.
* Доступ к этому репозиторию на GitHub.
* Google Таблица медиамониторинга, открытая на чтение по ссылке.
  Проверить: таблица → **Доступ** (Share) → «Любой, у кого есть ссылка», роль
  «Читатель».

Ничего устанавливать на компьютер не нужно — всё делается в браузере.

---

## Шаг 1. Создать проект Cloudflare Pages

1. Зайти на [dash.cloudflare.com](https://dash.cloudflare.com).
2. В левом меню выбрать **Workers & Pages**.
3. Нажать **Create application** → вкладка **Pages** → **Connect to Git**.
4. Подключить GitHub — **Connect GitHub**. На странице GitHub:
   * выбрать **Only select repositories**;
   * отметить этот репозиторий;
   * нажать **Install & Authorize**.
5. Вернувшись в Cloudflare, выбрать репозиторий и нажать **Begin setup**.
6. Заполнить форму. Поля, которых нет в таблице, не трогать:

   | Поле | Что вписать |
   |---|---|
   | Project name | `viferon-media-dashboard` |
   | Production branch | `main` |
   | Framework preset | `None` |
   | Build command | **оставить пустым** |
   | Build output directory | `public` |
   | Root directory (advanced) | не трогать |
   | Environment variables | не трогать, см. шаг 2 |

7. Нажать **Save and Deploy**.

Сборки как таковой нет — Cloudflare просто раскладывает содержимое папки
`public`, обычно это 20–40 секунд.

**Проверка.** Появился экран **Success! Your project is deployed to
`viferon-media-dashboard.pages.dev`**.

> Имя проекта задаёт адрес технической выдачи. Если оно занято, Cloudflare
> предложит другое — запомните его, дальше пригодится.

---

## Шаг 2. Переменные окружения

**Ничего делать не нужно.** `MEDIA_SHEET_ID` и `CACHE_TTL` лежат в
`wrangler.toml`, а для Pages этот файл — источник истины: в разделе
**Settings → Variables and Secrets** вы их увидите, но поля будут недоступны для
редактирования.

Менять значения нужно **в файле**, а не в интерфейсе: правите, коммитите —
Cloudflare пересобирает проект сам.

Если хотите управлять переменными из интерфейса или спрятать ID таблицы как
**Secret** — удалите из `wrangler.toml` блок `[vars]`, запушьте и задайте
значения в **Settings → Variables and Secrets** отдельно для **Production** и
**Preview**.

---

## Шаг 3. Проверить на технической выдаче

Откройте `https://viferon-media-dashboard.pages.dev`.

**Проверка.** Виден отчётный период и упоминания Виферона, вверху **нет жёлтой
полосы** про снапшот, внизу написано **«Источник: Google Таблица»**.

Если полоса есть — прослойка не поднялась: откройте `/api/media` напрямую и
посмотрите текст ошибки, дальше по таблице диагностики.

---

## Шаг 4. Подключить свой поддомен

**Не создавайте CNAME вручную.** Если запись появится в DNS раньше, чем домен
привязан к проекту, поддомен будет отдавать ошибку **522**.

1. Открыть проект: **Workers & Pages** → `viferon-media-dashboard`.
2. Вкладка **Custom domains** → **Set up a domain**.
3. Ввести поддомен целиком, например `viferon-media.dump.su`.
4. **Continue** — Cloudflare покажет запись, которую создаст:

   | Type | Name | Content |
   |---|---|---|
   | CNAME | `viferon-media` | `viferon-media-dashboard.pages.dev` |

5. Нажать **Activate domain**.

Статус будет меняться: **Initializing** → **Pending** → **Active**. Обычно 1–3
минуты, изредка до пятнадцати — в это время выпускается SSL-сертификат.

**Проверка.** В списке **Custom domains** статус **Active**, поддомен открывается
с замком в адресной строке.

---

## Шаг 5. Закрыть дашборд от посторонних (рекомендуется)

В разметке стоит `noindex, nofollow`, но от прямой ссылки это не защищает.
Домен уже проксируется через Cloudflare, поэтому туннель не нужен:

1. Левое меню → **Zero Trust** (при первом входе попросит выбрать план,
   бесплатного хватает).
2. **Access controls** → **Applications** → **Create new application**.
3. Тип — **Self-hosted and private**, затем **Add public hostname**.
4. Заполнить: **Application name** — `Viferon media`, **Domain** — ваш домен и
   поддомен, **Path** — пустой.
5. Политика: **Action** — **Allow**, **Include** — `Emails` со списком адресов
   либо `Emails ending in` и домен вашей почты.
6. **Create**.

**Проверка.** В режиме инкогнито Cloudflare просит почту и одноразовый код.

`/api/media` закроется вместе со страницей — так и нужно: дашборд обращается к
нему из уже авторизованного браузера.

---

## Как обновлять дальше

* **Данные.** Правьте Google Таблицу — дашборд подхватит изменения сам, максимум
  через `CACHE_TTL` секунд (сейчас 5 минут). Кнопка **Обновить** делает это
  мгновенно.
* **Код и настройки.** Любой коммит в `main` запускает новый деплой
  автоматически.
* **Откат.** Проект → **Deployments** → у нужного деплоя `···` → **Rollback to
  this deployment**.
* **Логи прослойки.** Проект → **Functions** → **Begin log stream**, затем
  обновить страницу дашборда.

## Если что-то пошло не так

| Что видите | Из-за чего | Что делать |
|---|---|---|
| Поддомен отдаёт **522** | CNAME создали вручную до привязки домена к проекту | В DNS зоны удалить запись поддомена, затем пройти шаг 4 заново |
| Домен «висит» в **Pending** дольше 15 минут | домен в другом аккаунте Cloudflare, не в том, где проект | Мастер привязки покажет TXT-запись для подтверждения — добавьте её в DNS |
| Жёлтая полоса «Показан локальный снапшот» | прослойка `/api/media` не отвечает | Открыть `/api/media` напрямую и смотреть текст ошибки — строки ниже |
| `/api/media` отдаёт **404** | в Build output directory указано не `public` | **Settings → Builds** → исправить на `public` → **Retry deployment** |
| **502**, `Google Sheets ответил 404` | неверный `MEDIA_SHEET_ID` | Сверить ID со ссылкой на таблицу: он между `/d/` и `/edit` |
| **502**, `gviz вернул ошибку` | у таблицы закрыт доступ по ссылке | Таблица → **Доступ** → «Любой, у кого есть ссылка», роль «Читатель» |
| **502**, `вернул не те данные: среди брендов нет Виферона` | лист таблицы переименовали | Сверить ярлык вкладки с названием в `BLOCKS` в `functions/api/media.js` |
| Правки в таблице не видны | ответ лежит в кэше | Нажать **Обновить** или подождать `CACHE_TTL` |
| В подвале `edge-кэш: STALE` | Google Таблицы временно недоступны, показан последний удачный ответ | Ничего не делать, пройдёт само |

---

## Приложение: деплой без подключения к GitHub

```bash
npm install
npx wrangler pages project create viferon-media-dashboard
npx wrangler pages deploy public
```

Поддомен подключается так же — через **Custom domains** в интерфейсе.

Учтите: проект, созданный прямой загрузкой (Direct Upload), **нельзя** потом
подключить к Git — придётся создавать заново.
