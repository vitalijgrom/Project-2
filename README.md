# Дашборд медиамониторинга Виферон

Сравнительный отчёт по эффективности: упоминания и тональность Виферона на фоне
13 конкурентов. Данные лежат в Google Таблице медиамониторинга, забираются через
прослойку на Cloudflare, отображаются без серверного рендеринга и без внешних
библиотек.

**Живая цепочка данных:** Google Таблица → Cloudflare Pages Function
(`/api/media`) → браузер.

## Что показывает

| Блок | Что отвечает |
|---|---|
| KPI-строка | упоминания Виферона, доля голоса, место в рейтинге, индекс лояльности, негатив — всё с изменением к прошлому периоду |
| Доля голоса | гантели «прошлый период → отчётный» по всем брендам, отдельно по упоминаниям, позитиву и негативу |
| Тональность | расходящаяся стопка: негатив влево, позитив вправо, нейтраль по центру |
| Индекс лояльности | сколько позитивных упоминаний приходится на одно негативное |
| Динамика Виферона | помесячно с 2016 года: упоминания, позитив, негатив, лояльность, консультанты |
| Виферон против конкурентов | линии по месяцам или годам, в абсолюте или в доле голоса; можно подсветить одного конкурента |
| KPI по годам | в количестве и в коэффициенте, с разбивкой по кварталам в подсказке |
| Активность и бан-контроль | посты, комментарии, репосты по годам; заблокированные аккаунты по месяцам |
| Таблица | все бренды отчётного периода с сортировкой и выгрузкой в CSV |

Дашборд подхватывает тему системы, имеет собственный переключатель
светлая/тёмная и раз в 5 минут тихо обновляет данные.

## Структура

```
public/
  index.html            разметка
  assets/styles.css     токены тем и базовые компоненты
  assets/media.css      компоненты, которые есть только у этого дашборда
  assets/common.js      форматирование, тултип, тема, загрузка данных
  assets/app.js         разбор данных, графики, фильтры, таблица
  data/media.json       снапшот таблицы на случай недоступности прослойки
functions/
  api/media.js          Cloudflare Pages Function — прослойка к Google Sheets
lib/
  sheets.js             доступ к gviz, edge-кэш, формирование ответа
scripts/
  snapshot.mjs          обновление снапшота (переиспользует код функции)
wrangler.toml           конфиг Pages: каталог сборки и переменные
```

## Как работает прослойка

`functions/api/media.js` отвечает на `GET /api/media`:

1. Забирает девять блоков данных из листов таблицы и приводит их к стабильной
   JSON-схеме.
2. Кэширует ответ на edge Cloudflare — Google отдаёт `no-store`, поэтому TTL
   держим сами (`CACHE_TTL`, по умолчанию 300 секунд).
3. Отдельно хранит **последний удачный ответ**. Если Google лёг, отдаётся он
   с заголовком `x-cache: STALE` — дашборд не белеет, а честно пишет об этом.
4. Не пускает ID таблицы в браузер: фронтенд знает только про `/api/media`.

Полезные заголовки ответа: `x-cache` (`HIT` / `MISS` / `BYPASS` / `STALE`) и
`x-data-source`. Принудительно обновить: `GET /api/media?refresh=1` — это же
делает кнопка «Обновить».

Если прослойка недоступна (например, открыли `public/` как статику), дашборд
загружает `data/media.json` и показывает баннер о том, что данные снапшотные.

## Требования к Google Таблице

Доступ: «Любой, у кого есть ссылка — читатель». Ничего публиковать в веб
отдельно не нужно.

У листов этой таблицы многоуровневые шапки, а на одном листе рядом лежит по
несколько блоков, поэтому каждый блок берётся точным диапазоном — список в
массиве `BLOCKS` в `functions/api/media.js`. Диапазон **всегда начинается со
строки шапки**: gviz предсказуемо работает только в режиме `headers=1`.

Две вещи, о которые легко споткнуться при правках:

* **Названия листов должны совпадать с ярлыками вкладок символ в символ.** Если
  имя не найдено, gviz не отдаёт ошибку, а молча возвращает первый лист таблицы.
  Разбор проверяет, что среди брендов есть Виферон, и падает с внятной ошибкой,
  если пришло не то.
* **Выгрузка в xlsx режет названия листов до 31 символа** — «Аналитика год к году
  перевернуто» превращается в «…перевернут». Сверяться нужно с ярлыком вкладки,
  а не с выгрузкой.

## Деплой

Пошаговая инструкция — в **[DEPLOY.md](DEPLOY.md)**. Коротко:

1. Cloudflare Dashboard → **Workers & Pages** → **Create** → **Pages** →
   **Connect to Git**, выбрать этот репозиторий.
2. Framework preset — **None**, Build command — пустой, Build output
   directory — **`public`**.
3. Deploy. Каталог `functions/` Cloudflare подхватывает сам.

Переменные `MEDIA_SHEET_ID` и `CACHE_TTL` заданы в `wrangler.toml`. Для Pages
этот файл — источник истины: в дашборде переменные видно, но редактировать их
нельзя. Чтобы управлять ими из интерфейса, удалите блок `[vars]` и задайте
значения в **Settings → Variables and Secrets** отдельно для Production и
Preview.

## Локальная разработка

```bash
npm install
npm run dev          # wrangler pages dev public → http://localhost:8788
```

`wrangler pages dev` поднимает и статику, и функцию, поэтому `/api/media`
работает локально ровно так же, как в проде.

Без wrangler можно открыть просто статику (`npx serve public`) — дашборд
переключится на снапшот и покажет об этом баннер.

Обновить снапшот:

```bash
npm run snapshot
```

## Настройка под себя

* **Блоки данных** — массив `BLOCKS` в `functions/api/media.js`: лист и диапазон
  каждого куска.
* **Герой дашборда** — константа `HERO` в `public/assets/app.js`. Поменяйте её,
  и акцент на графиках перейдёт на другой бренд.
* **Частота автообновления** — `CONFIG.autoRefreshMs` там же.
* **Палитра** — CSS-переменные в начале `styles.css` и `media.css`. Пара
  «позитив/негатив» — синий и красный: она проверена на различимость при
  дальтонизме в обеих темах, зелёный с красным такую проверку не проходят.
